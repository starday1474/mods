# RPG 모드 + 모드팩 설계 문서

작성일: 2026-11-16 · 상태: 사용자 승인 대기

## 1. 목적과 배경

친구들끼리 함께 플레이할 **전통적인 RPG 경험**을 마인크래프트에 만든다. 두 부분으로 이루어진다.

1. **우리 RPG 모드 (직접 개발, Java)** — 여신의 질의로 정해지는 직업군·재능·적성, 숙련도 성장, 스킬, 무기·활·마법, 소환·유물·치유, 여신의 서.
2. **모드팩** — 보스·던전·차원·최적화는 다른 모드를 쓰고, 그 모드들의 한글 패치와 보스 재조정을 한다. 우리 모드도 이 모드팩에 들어간다.

- 대상: 사용자와 친구들(내수용). 공개 배포하지 않는다. 유튜브 영상 촬영 가능성 있음.
- 플레이 기간: 사실상 무기한.
- 레벨업하며 던전·미궁을 공략하는 전통 RPG가 핵심 경험이다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 첫 접속 때 여신의 질의로 **각자 다른 캐릭터**가 되고, 친구들 사이에 자연스럽게 역할 분담이 생긴다.
- 성장(숙련도·스킬) → 장비 → 던전/보스 공략의 흐름. 단계는 시간이 아니라 보스 처치로 열린다.
- **화면과 조작이 단순하다**: 창은 책 한 권, 스킬 슬롯 4칸, 패시브 자동.
- 모든 텍스트가 한국어. 우리 모드는 한국어가 기본 언어.
- 친구들이 가이드만 보고 설치·접속·업데이트할 수 있고, 업데이트는 자동.
- 사용자 PC(RAM 16GB)에서 월드를 열고 친구들이 접속해 쾌적하게 플레이.
- **일찍 같이 놀기 시작**하고, 우리 모드는 한 유형씩 늘려 간다.

**비목표**
- 공개 배포, 전용 서버/서버팩, 지도 모드.
- 처음부터 9개 유형을 한꺼번에 완성하는 것.

**반목표 (돌아가도 실패로 보는 것)**
- 한 캐릭터가 모든 역할을 다 하는 "잡캐".
- 창·단축키·신경 쓸 수치가 많아 복잡한 상태.
- 친구마다 버전이 달라 접속이 안 되는 상태.
- 영어가 섞여 알아볼 수 없는 상태.
- 성장이 무의미하거나, 단순 반복 노가다 없이는 진행 불가.
- 사용자 PC에서 끊기거나 튕기는 상태.

## 5. 우리 RPG 모드

### 5.1 첫 접속: 여신의 질의
- 처음 월드에 들어오면 **여신이 나타나** 질문한다. 선택지 문구는 성향이 **어느 정도 드러나게** 쓴다 (숫자는 안 보임).
- **3단계**
  1. 첫 질문 몇 개 → **직업군**
  2. 다음 질문들 → **하위 유형**
  3. 마지막 질문들 → 두 분야의 **재능·적성 값**
- 결과는 **영구적**이다. 바꿀 수 없다.
- 질의가 끝나면 여신이 **여신의 서**(아이템)를 건넨다.
- 멀티에서 각 플레이어는 처음 접속할 때 각자 질의를 받는다.
- 질문·선택지·결과 매핑은 데이터 파일(JSON)로 두어 코드 수정 없이 고칠 수 있게 한다.

### 5.2 직업군과 하위 유형 (3 × 3 = 9)

| 직업군 | 분야 | 하위 유형 | 성격 |
|---|---|---|---|
| **전위** | 검술, 방어술 | 밸런스형 | 검과 방패, 공수 균형 |
| | | 탱킹형 | 방패·방어술 중심, 어그로 |
| | | 인파이트 | 대검·쌍검, 고위험 고피해 |
| **후위 딜러** | 궁술, 원소 마법 | 궁수 | 활, 단일 대상 고피해 |
| | | 원소술사 | 지팡이, 광역 마법 |
| | | 마궁 | 원소를 실은 화살, 혼합 |
| **후위 서포터** | 소환술, 유물술 | 소환사 | 싸우는 소환수 |
| | | 유물사 | 유물을 깨워 아군 강화, 장비에 유물의 힘 각인 |
| | | 치유사 | 회복 정령 소환, 회복 효과 — 파티 회복 담당 |

- 같은 직업군 스킬은 공유하고, **하위 유형마다 전용 가지**가 하나 더 열린다 (예: 탱킹형만 도발 계열).
- 하위 유형 구성 중 마궁·치유사·밸런스형 등 일부 이름과 세부는 설계자 제안이며 사용자가 대체로 수락함.

### 5.3 성장: 숙련도 · 재능 · 적성 · 지식
- **숙련도**: 분야별 레벨. 그 분야 장비·스킬을 쓰면 오른다.
- **재능 = 출발선**: 그 분야의 시작 숙련도/기본 능력.
- **적성 = 경험치 배율**: 그 분야 숙련도가 오르는 속도. 영구.
- **지식**: 고서를 읽어 얻는다. 경험치 배율을 추가로 올리지만 적성 값 자체는 바뀌지 않는다.
- 실제 성장 속도 = 적성 + 지식.
- 표시: 재능·적성은 숫자 대신 별(★)로.
- Project MMO / Pufferfish's Skills는 **사용하지 않는다** (우리 모드가 대체).

### 5.4 스킬
- **자기 직업군 스킬만 배울 수 있다.**
- 얻는 방법은 여러 가지:
  | 방법 | 얻는 것 |
  |---|---|
  | 숙련도 달성 | 기본 스킬 (자동 습득) |
  | 스킬북 (던전 상자) | 중급 스킬 |
  | 보스 처치 | 상위·고유 스킬 |
  | 고서 | 스킬이 아니라 **지식** |
- **슬롯 4칸**에 액티브 스킬을 끼운다. **패시브는 배우면 자동 적용**.
- **회피·가드**는 Epic Fight 기본 키로, 슬롯 밖 고정.
- 무기 고유 공격·무기 스킬은 Epic Fight 애니메이션 시스템 위에 우리가 만든다.
- 전투 중 신경 쓸 수치: 체력, 마력, Epic Fight 스태미나.

### 5.5 다른 직업군의 장비를 쓸 때
- **쓸 수는 있지만 스킬은 못 배우고 못 쓴다.**
  | 장비 | 다른 직업군일 때 |
  |---|---|
  | 마법 | 마법이 담긴 **스크롤**이나 **마법 무기**로만. 마력 총량 낮음 |
  | 활 | 쏠 수 있으나 여러 단점 (예: 당기는 속도·명중·피해 감소 — 수치는 밸런스 때) |
  | 검 | 기본 공격만, 검술 스킬 없음 |

### 5.6 스크롤
- **빈 스크롤은 누구나 만들 수 있다.**
- **마법을 담는 건** 마법을 다루는 사람(원소술사·마궁·소환사·치유사)이 자기가 배운 마법으로 한다.
- 마법 계열이 아니면 **그에 준하는 매개체**(예: 마력을 품은 제단, 마력석)가 있어야 담을 수 있다. 형태는 추후 결정.
- 유물사는 스크롤 각인을 하지 않는다.

### 5.7 마력
- 직업군마다 마력 총량이 크게 다르다. 다른 직업군은 낮다.

### 5.8 여신의 서 (UI)
- 여신이 주는 **책 아이템**. 손에 들고 우클릭 또는 단축키 하나로 연다.
- 창을 여러 개 두지 않고 **책처럼 페이지를 넘긴다.**
  1. **능력치**: 직업군·하위 유형, 분야별 숙련도, 재능·적성(★), 지식, 마력
  2. **스킬**: 직업군을 중심으로 분야 → 스킬로 뻗는 **마인드맵**. 배운 스킬 밝게, 못 배운 스킬 흐리게, 미발견은 `???`. 마우스를 올리면 얻는 방법 힌트. 클릭해서 슬롯 4칸에 장착
  3. **지식**: 읽은 고서와 오른 배율
  4. **여신의 말씀**: 질의 때 고른 답과 여신의 평가 (이야기 페이지)
- 마인드맵은 순서 제한(선행 스킬) 없이 "무엇이 어디에 속하는지" 보여 주는 지도.

### 5.9 그림과 모델
- 전부 Claude가 만들고, 렌더링 스크린샷으로 사용자 검토 후 수정.
- 아이템 아이콘: 16×16 픽셀.
- **무기: 3D 큐브 모델**(손·땅), 인벤토리는 2D 아이콘. NeoForge의 표시 상황별 모델 분리 기능 사용.
- **여신**: 사람 형태 기본 모델 + 스킨 + 날개·후광 장식.
- **소환수·정령**: 단순한 형태, GeckoLib 모델·애니메이션.
- 그림·모델 파일은 코드와 분리해 나중에 교체하기 쉽게.
- 무기 수는 하위 유형별·단계별 대표 무기 위주로 관리 (개수는 구현 계획에서).

### 5.10 기술 구성
- NeoForge 1.21.1, Java 21, Gradle (NeoForge MDK 기반).
- 의존: **Epic Fight API**(무기 동작·무기 스킬), **GeckoLib**(여신·소환수 애니메이션), Curios(유물 슬롯이 필요하면).
- 스킬·무기 수치·여신 질문·결과 매핑은 **데이터 파일(JSON, 데이터팩 형식)**.
- 플레이어 데이터(직업군·재능·적성·숙련도·지식·스킬·슬롯)는 플레이어에 저장, 멀티 동기화.
- 기본 언어 ko_kr, 보조 en_us.
- 빌드된 jar는 **GitHub Releases**에 올리고 packwiz가 그 URL을 가리킨다.

- AI 번역 후 검수. 아이템은 용어 통일·정확성, 스토리·퀘스트·설정글은 다듬기.
- 용어집을 저장소에 두고 우리 모드와 다른 모드의 용어를 통일.
- 공개 저장소이므로 **다른 사람의 한글 패치는 넣지 않는다.**

### 6.4 보스 재조정
- 대격변 등 보스 수치를 단계에 맞춰 조정 (KubeJS 속성 / 설정).
- KubeJS로 페이즈 전환 시 소환·장판·추가 투사체 등 패턴 추가.
- 드래곤·위더는 강화 모드 + 수치 조정.
- KubeJS로 불가능한 것만 Java (우리 모드 안에 넣거나 별도 소규모 애드온).
- 보스 밸런스는 **역할이 나뉜 파티**(전위·딜러·서포터) 기준. Multiplayer Bosses로 인원수 보정.

## 7. 열린 질문 (사용자 확인 필요)

1. **모드팩 먼저 단계의 성장 시스템**: 우리 모드가 나오기 전 모드팩만으로 플레이할 때는 레벨업 시스템이 없다. 그 기간에 임시로 Project MMO 등을 넣을지, 성장 없이 보스·던전만 즐길지.
2. **외부 무기·마법 모드**: Simply Swords, Epic Knights, Iron's Spells 등은 우리 모드의 직업군·스킬 규칙을 우회한다. 모드팩 먼저 단계에서만 쓰고 우리 모드가 들어오면 뺄지, 처음부터 넣지 않을지.
3. **Apotheosis**: 장비 등급·옵션은 우리 무기와 겹칠 수 있다. 유지할지.
