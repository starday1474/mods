# RPG 모드 + 모드팩 설계 문서

작성일: 2026-11-16 · 상태: 사용자 승인 대기

## 1. 목적과 배경

친구들끼리 함께 플레이할 **전통적인 RPG 경험**을 마인크래프트에 만든다. 두 부분으로 이루어진다.

1. **우리 RPG 모드 (직접 개발, Java)** — 캐릭터 만들기(무기 선택·포인트 분배)로 정해지는 직업군·재능·적성, 숙련도 성장, 스킬, 무기·활·마법, 소환·유물·치유, 여신의 서.
2. **모드팩** — 보스·던전·차원·최적화는 다른 모드를 쓰고, 그 모드들의 한글 패치와 보스 재조정을 한다. 우리 모드도 이 모드팩에 들어간다.

- 대상: 사용자와 친구들(내수용). 공개 배포하지 않는다. 유튜브 영상 촬영 가능성 있음.
- 플레이 기간: 사실상 무기한.
- 레벨업하며 던전·미궁을 공략하는 전통 RPG가 핵심 경험이다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 첫 접속 때 무기와 재능·적성을 골라 **각자 다른 캐릭터**가 되고, 친구들 사이에 자연스럽게 역할 분담이 생긴다.
- 성장(숙련도·스킬) → 장비 → 던전/보스 공략의 흐름. 단계는 시간이 아니라 보스 처치로 열린다.
- **화면과 조작이 단순하다**: 창은 책 한 권, 스킬 슬롯 4칸, 패시브 자동.
- 모든 텍스트가 한국어. 우리 모드는 한국어가 기본 언어.
- 친구들이 가이드만 보고 설치·접속·업데이트할 수 있고, 업데이트는 자동.
- 사용자 PC(RAM 16GB)에서 월드를 열고 친구들이 접속해 쾌적하게 플레이.
- **모드팩을 완성한 뒤 친구들에게 전달**한다. 그 전까지는 사용자가 혼자 테스트한다.

**비목표**
- 공개 배포, 전용 서버/서버팩, 지도 모드.
- 처음부터 9개 유형을 한꺼번에 완성하는 것.

**반목표 (돌아가도 실패로 보는 것)**
- 한 캐릭터가 모든 역할을 **쉽게** 다 하는 상태. (다른 분야 숙련도는 오르지만 느리고, 스킬은 자기 직업군만 — 5.3)
- 창·단축키·신경 쓸 수치가 많아 복잡한 상태.
- 친구마다 버전이 달라 접속이 안 되는 상태.
- 영어가 섞여 알아볼 수 없는 상태.
- 성장이 무의미하거나, 단순 반복 노가다 없이는 진행 불가.
- 사용자 PC에서 끊기거나 튕기는 상태.

## 5. 우리 RPG 모드

### 5.1 첫 접속: 캐릭터 만들기 (2026-11-22 사용자 결정으로 여신 질의를 대체)
- 여신 질의·여신 모델·여신 연출은 **폐지**한다.
- 처음 월드에 들어오면 **캐릭터 만들기 화면**이 열린다. 두 단계다.
  1. **쓰고 싶은 무기를 고른다 → 하위 유형이 정해진다.** 무기 카드마다 플레이 방식 설명이 붙는다.
     | 무기 | 하위 유형 |
     |---|---|
     | 한손검 + 방패 | 밸런스형 |
     | 방패 + 둔기 | 탱킹형 |
     | 대검 · 쌍검 | 인파이트 |
     | 장궁 | 궁수 |
     | 지팡이 | 원소술사(마법사) |
     | 소환석 | 소환사 |
     | 성표(치유의 지팡이) | 치유사 |
     | 유물(반지·바늘) | 유물사 |
     - 마궁은 교체 예정이라 목록에서 뺀다. 아직 구현하지 않은 하위 유형은 "준비 중"으로 보이고 고를 수 없다.
  2. **재능·적성 포인트 분배**: 그 직업군의 두 분야에 대해 재능(시작 레벨)과 적성(성장 속도) 4칸에 별(★)을 직접 나눠 넣는다.
     - 각 칸은 ★1~★5, 총 **12개**(평균 ★3)를 모두 써야 확정된다. 값은 `tuning/allocation.json`(빌더 결정, 플레이 테스트로 조정).
     - 별 → 시작 레벨·성장 배율 표는 기존 그대로(`growth.json`).
- 결과는 **영구적**이다. 바꾸는 방법은 두 가지다.
  - **관리자(치트) 전용 아이템**: 크리에이티브/OP 전용, 즉시 다시 만들기 (테스트용).
  - **게임 안 재선택: "재각성의 결정"** — 아주 비싼 재료(후반 보스 재료급)로 만드는 소모품. 쓰면 캐릭터 만들기 화면이 다시 열리고, **숙련도·배운 스킬·슬롯·쿨타임이 초기화**된다(지식·고서는 유지). 재료는 빌더 초안, 사용자 검토.
- 확정하면 **모험가의 서**(아이템)를 받는다.
- 멀티에서 각 플레이어는 처음 접속할 때 각자 만든다.
- 무기 카드·설명·하위 유형 매핑, 포인트 규칙은 데이터 파일(JSON)이다.

### 5.2 직업군과 하위 유형 (3 × 3 = 9)

| 직업군 | 분야 | 하위 유형 | 성격 |
|---|---|---|---|
| **전위** | 검술, 방어술 | 밸런스형 | 검과 방패, 공수 균형 |
| | | 탱킹형 | 방패·방어술 중심, 어그로 |
| | | 인파이트 | 대검·쌍검, 고위험 고피해 |
| **후위 딜러** | 궁술, 원소 마법 | 궁수 | 활, 단일 대상 고피해 |
| | | 원소술사 | 지팡이, 광역 마법 |
| | | 마궁 | 원소를 실은 화살, 혼합 — **나중에 다른 하위 유형으로 교체 예정** (사용자 2026-11-16) |
| **후위 서포터** | 소환술, 유물술 | 소환사 | 싸우는 소환수 |
| | | 유물사 | 여러 유물(아이템)을 장착해 각 유물의 고유 능력을 다룸 (5.13) |
| | | 치유사 | 회복 정령 소환, 회복 효과 — 파티 회복 담당 |

- 같은 직업군 스킬은 공유하고, **하위 유형마다 전용 가지**가 하나 더 열린다 (예: 탱킹형만 도발 계열).
- 하위 유형 구성 중 마궁·치유사·밸런스형 등 일부 이름과 세부는 설계자 제안이며 사용자가 대체로 수락함.

### 5.3 성장: 숙련도 · 재능 · 적성 · 지식
- **숙련도**: 분야별 레벨. 그 분야 장비·스킬을 쓰면 오른다.
- **재능 = 출발선**: 그 분야의 시작 숙련도/기본 능력.
- **적성 = 경험치 배율**: 그 분야 숙련도가 오르는 속도. 영구.
- **지식**: 고서를 읽어 얻는다. 경험치 배율을 추가로 올리지만 적성 값 자체는 바뀌지 않는다.
- 실제 성장 속도 = 적성 + 지식.
- **다른 직업군 분야도 숙련도가 오른다(잡캐 가능)**, 대신 아주 느리게(고정 낮은 배율, 적성·지식 미적용). 스킬은 여전히 자기 직업군 것만. (2026-11-16 사용자 결정)
- 표시: 재능·적성은 숫자 대신 별(★)로.
- Project MMO / Pufferfish's Skills는 **사용하지 않는다** (우리 모드가 대체).

### 5.4 스킬
- **자기 직업군 스킬만 배울 수 있다.**
- 얻는 방법은 여러 가지:
  | 방법 | 얻는 것 |
  |---|---|
  | 숙련도 달성 | 기본 스킬 (자동 습득) |
  | 스킬북 (던전 상자) | 중급 스킬 |
  | 보스 처치 | 상위·고유 스킬 — **보스 유형에 따라 주는 스킬이 다르다** (5.4.1) |
  | 고서 | 스킬이 아니라 **지식** |
#### 5.4.1 보스 스킬
- 주요 보스마다 유형(예: 근접형, 원거리·마법형, 소환·주술형)을 정하고, 그 유형에 맞는 스킬을 준다.
- 해석(설계자): 보스 유형에 맞는 직업군 스킬을 주고, 처치에 참여한 해당 직업군 플레이어가 각자 배운다. 맞지 않는 직업군은 대체 보상(재료 등). 대상은 주요 보스 약 10개 내외.

- **슬롯 4칸**에 액티브 스킬을 끼운다. **패시브는 배우면 자동 적용**.
- **회피·가드**는 Epic Fight 기본 키로, 슬롯 밖 고정.
- 무기 고유 공격·무기 스킬은 Epic Fight 애니메이션 시스템 위에 우리가 만든다.
- 전투 중 신경 쓸 수치: 체력, 마력, Epic Fight 스태미나.

### 5.5 다른 직업군의 장비를 쓸 때
- **쓸 수는 있지만 스킬은 못 배우고 못 쓴다.**
  | 장비 | 다른 직업군일 때 |
  |---|---|
  | 마법 | 마법이 담긴 **스크롤**이나 **마법 무기**로만. 마력 총량 낮음 |
  | 활 | 쏠 수 있으나 여러 단점 (예: 당기는 속도·명중·피해 감소 — 수치는 밸런스 때) |
  | 검 | 기본 공격만, 검술 스킬 없음 |

### 5.6 스크롤
- **빈 스크롤은 누구나 만들 수 있다.**
- **마법을 담는 건** 마법을 다루는 사람(원소술사·마궁·소환사·치유사)이 자기가 배운 마법으로 한다.
- 마법 계열이 아니면 **그에 준하는 매개체**(예: 마력을 품은 제단, 마력석)가 있어야 담을 수 있다. 형태는 추후 결정.
- 유물사는 스크롤 각인을 하지 않는다.

### 5.7 마력
- 직업군마다 마력 총량이 크게 다르다. 다른 직업군은 낮다.

### 5.7.1 마법 체계 (사용자 결정 2026-11-16)
- **나만의 마법 만들기** (사용자 제안 2026-11-18, 계획 4에서 상세화): 마법을 고정된 목록으로만 주지 않고 조합으로 만든다.
  - **형태** 선택: 화살, 망치, 창, 구체, 장판, 벽, 소환체 등 마법이 어떤 모양으로 나가는지
  - **속성** 추가: 불, 얼음, 번개, 바람, 땅, 빛, 어둠 등 (여러 속성 조합 가능 여부·상한은 서클로 제한)
  - **특성/성질** 추가: 관통, 추적, 분열, 폭발, 지속, 연쇄 등
  - 조합 결과의 위력·마력 비용·영창 시간은 규칙으로 계산하고, 만든 마법은 마법서 칸이나 스킬 4칸에 넣어 쓴다. 높은 서클일수록 더 많은 속성·특성을 붙일 수 있다.
- **Iron's Spells 방식을 참고해 우리 모드에 새로 만든다** (모드 자체는 넣지 않음).
  - 시전 형태: 즉시 / 영창(버틴 뒤 발동) / 유지(누르는 동안) / 차지(모았다 놓기).
  - 마력·마력 회복, 마법별 쿨타임, 학파 위력 옵션(예: 화염 위력 +10%), 마법 레벨(같은 마법도 레벨이 오르면 강해짐).
  - 스크롤은 5.6 그대로.
- **서클 = 마법사 등급**: 1서클 → 9서클로 성장. 서클이 오르면 쓸 수 있는 마법 등급(1~9서클 마법), 마력 총량, 동시에 유지할 수 있는 마법 수가 늘어난다.
  - 대상: **원소술사(마법사)·소환사·치유사** (사용자 확정 2026-11-16). 서클은 각자의 주 마법 분야 숙련도로 오른다. 숙련도 레벨 `(n-1)×6`에 n서클 (0→1서클, 48→9서클), **레벨이 오르면 자동 승급** (사용자 결정 2026-11-16, 승급 시험 없음).
  - 시전 연출: 서클 수만큼 겹친 마법진 고리 (예: 3서클 마법 = 고리 3겹).
- **마법 직업의 스킬 칸 = 자체 4칸 + 마법서 확장** (사용자 결정 2026-11-16).
  - 다른 직업처럼 **자체 스킬 칸 4개**(단축키)를 가진다.
  - **마법서는 외부 확장 스킬창**: 장착하면(Curios 칸) 추가 마법 칸이 열린다. 마법서 등급마다 칸 수가 다르다. 마법서 칸의 마법은 **륜**(원형 선택 메뉴)으로 고른다 — 키를 누르고 있으면 원형으로 펼쳐지고 마우스 방향으로 골라 놓으면 선택, 기본 시전 키로 시전.
  - 근접·궁수 직업은 스킬 4칸만.

### 5.8 모험가의 서 (UI) — 2026-11-22 '여신의 서'에서 이름 변경

  3. **지식**: 읽은 고서와 오른 배율

### 5.13 유물 (유물사)
- 유물사는 무언가를 새로 만드는 직업이 아니라, **여러 유물 아이템을 다루는** 직업이다. 유물마다 고유 능력이 있다.
  - 예: **천의 바늘** — 공중을 떠다니는 바늘들을 조종해 공격·방어.
  - 예: **불의 반지** — 끼면 불을 다루는 능력(화염 공격·불길 조종)을 얻는다.
- 유물은 Curios 칸(반지·목걸이·장신구 등)이나 손에 장착한다. 장착한 유물의 능력이 그 유물 전용 스킬로 열리고, 유물사의 스킬 슬롯 4칸에 끼워 쓴다.
- 유물 조합이 곧 빌드다. 어떤 유물을 들고 가느냐로 역할(딜·보조·방어)이 바뀐다.
- 유물술 숙련도가 오르면 유물 능력이 강해지거나 새 능력이 열린다.
- 얻는 곳: 던전 상자, 보스 처치, 미궁 보상. 유물은 모두 **우리가 직접 만든다** (Relics 모드·Reliquified 계열은 넣지 않음).
- 다른 직업군이 유물을 끼면(5.5 규칙): 유물의 능력은 못 쓰고, 작은 기본 효과(예: 불 저항)만 받는다. (2026-11-16 사용자 확정)
- 유물사는 스크롤 각인도, 장비 각인도 하지 않는다.
- **유물 수: 약 20종** (사용자 2026-11-18). 유물 전체 컨셉(세계관·계열·조합)을 먼저 짠 뒤 추가한다 — 유물사 계획에서.

### 5.14 궁수의 활 (조작형)
- **궁수만** 조작형 활 기술을 쓴다. 다른 직업군은 기본 활(당겨서 쏘기)만, 단점 포함 (5.5).
- 기술은 스킬 슬롯이 아니라 **입력 조합으로 나간다**. 궁술 숙련도가 오르면 하나씩 열린다. 스킬 4칸은 조작으로 안 나오는 것(강화 효과, 보스 스킬)에 쓴다.
- **손맛 기준: 몬스터헌터 월드(기본판)의 활 플레이 흐름** (사용자 결정 2026-11-16, 활을 쓸 친구가 몬헌을 좋아함). 조작 흐름·타이밍·리듬은 같은 계열로 맞추되, **모션·기술 이름·외형은 우리가 새로 만든다** (특정 게임 복제 금지).
- 기술 구성(이름은 가칭, 사용자 검토):
  | 기술 | 내용 |
  |---|---|
  | 차지 사격 | 당긴 시간에 따라 1~3단계. 단계가 오를수록 화살 수·위력 증가 |
  | 연속 사격 | 쏜 직후 이어 쏘면 차지 단계 유지·상승 |
  | 차지 스텝 | 회피(Epic Fight 회피 키)하면 차지 단계 +1, 스태미나 소모 |
  | 강사격 | 연계 중 버티고 쏘는 강한 다발 사격 (연속 2회까지) |
  | 곡사 ("하늘비") | 하늘로 쏘아 범위에 화살비 |
  | 관통 일격 ("별꿰뚫기") | 버티는 자세로 쏘는 길게 꿰뚫는 강한 한 방, 스태미나 크게 소모 |
  | 빠른 사격 | 이동 중 차지 없이 바로 쏘기 |
- **장궁이 기본** (사용자 결정 2026-11-17). 궁수 모션은 **실제 장궁 사법**(영국 장궁, 궁도, 국궁: 옆으로 선 넓은 자세, 귀·뺨까지 깊은 당김, 활을 세우거나 비스듬히 눕힌 연사, 발사 후 시위 손이 뒤로 빠지는 여운)을 기준으로 우리가 만든다. 같은 장궁을 다루므로 몬헌의 손맛과 자연스럽게 닮게 하되, 특정 게임 동작을 프레임 단위로 따라 만들지 않는다. 미리보기에서 활은 장궁 길이로 그린다.
- **활 종류: 5종** (사용자 2026-11-18). 각 활이 단계별 사격 유형·특성이 다르다.
- **활마다 단계별 사격 유형**이 다르다 (연사형·관통형·확산형) → 활 장비마다 개성.
- **화살 강화 병은 쓰지 않는다** (사용자 결정 2026-11-16).
- **벽 타고 뛰어들어 사격, 화살 찌르기(근접)는 넣지 않는다** (사용자 결정 2026-11-22). 클러치 클로·슬링어 연계기도 없다.
- 0단계에서 특수 사격은 **퀵샷**(짧은 3발 산탄)이고, 1단계 이상에서는 강사격이다. 차지 스텝은 최고 단계를 유지해 준다. 곡사는 강사격 직후 쓰면 단계를 유지한다. 세부 흐름은 `docs/design/motion-principles.md` 3.2.1에 정리되어 있다.
- **궁수의 활 기술은 화살을 소모하지 않는다** (사용자 결정 2026-11-16). 다른 직업군의 기본 활 사용은 바닐라처럼 화살을 쓴다.
- **발사 방식: 동작 중심** (사용자 결정 2026-11-16, Epic Fight 총 애드온 느낌). 사격은 Epic Fight 공격 동작의 한 부분이고, 대부분의 사격은 실제 화살 엔티티 없이 **발사 순간 조준 방향으로 즉시 판정**하고 화살 잔상·빛줄기 효과만 보인다. 곡사처럼 날아가는 모습이 중요한 기술만 실제 투사체를 쓴다. 근접 무기처럼 동작·경직·연계가 끊기지 않게 하는 것이 목적.
- 참고 구현: 모드팩에 있는 **Weapons of Miracles의 엔더 블래스터**(`wom:ender_blaster`, 권총). 사격이 Epic Fight 공격 동작 클래스(`EnderblasterShootAttackAnimation`, 레이저는 `EnderBlasterLazerAnimation`)로 되어 있고, 일부는 실제 탄(`EnderBullet`), 일부는 동작+파티클로만 보인다. 한손·양손 콤보, 조준·재장전 동작 포함. 우리 활은 이 구조를 참고해 우리 코드·동작으로 만든다.
- **적정 거리**: 거리에 따라 피해가 달라지는 최적 거리 개념.
- 차지 단계는 조준점 옆에 작게 표시. 차지·회피 모두 Epic Fight 스태미나 사용.
- **조작 체계는 몬스터헌터 월드(기본판) 활과 같은 구조로 만든다** (사용자 결정 2026-11-17: 몬헌을 오래 한 친구가 "몬헌에서 하던 거라 익숙하다"고 느끼는 것이 목표). 조작·규칙·타이밍은 최대한 같게, **모션·이름·외형만 우리 것**.
  - 입력 매핑 초안 (마우스·키보드, 친구 검수 후 확정):
    | 월드의 개념 | 우리 입력 |
    |---|---|
    | 사격 버튼 꾹 → 차지, 떼면 발사 | 우클릭 꾹 → 떼면 발사 (1→3단계) |
    | 사격 직후 다시 사격 → 다음 사격 차지 단계 상승 | 발사 직후 우클릭 |
    | 차지 스텝 (사격 중 회피 → 단계 상승) | 사격 직후 Epic Fight 회피 키 |
    | 강사격 (사격 후 특수 사격, 연속 2회) | 발사 직후 좌클릭 (최대 2회) |
    | 곡사 (강사격 후 이어서 / 조준 중 특수 사격) | 강사격 후 좌클릭, 또는 웅크리기+좌클릭 |
    | 관통 일격 (사격+특수 동시) | 좌클릭+우클릭 동시 |
    | 단계 상한 +1 스킬 | 궁술 숙련도 보상 또는 장비 옵션으로 4단계 |
  - 정확한 버튼 순서·타이밍(입력 허용 시간, 단계 상승 규칙)은 계획 4 시작 전에 **친구에게 확인**받아 맞춘다.
- 정확한 입력 배치는 구현 계획(계획 4)에서 정하고 사용자 테스트로 조정.

### 6.3 한글 패치 리소스팩
- packwiz로 배포, 기본 활성화. `assets/<modid>/lang/ko_kr.json`.
- AI 번역 후 검수. 아이템은 용어 통일·정확성, 스토리·퀘스트·설정글은 다듬기.
- 용어집을 저장소에 두고 우리 모드와 다른 모드의 용어를 통일.
- 공개 저장소이므로 **다른 사람의 한글 패치는 넣지 않는다.**

### 6.4 보스 재조정
- 대격변 등 보스 수치를 단계에 맞춰 조정 (KubeJS 속성 / 설정).
- KubeJS로 페이즈 전환 시 소환·장판·추가 투사체 등 패턴 추가.
- 드래곤·위더는 강화 모드 + 수치 조정.
- KubeJS로 불가능한 것만 Java (우리 모드 안에 넣거나 별도 소규모 애드온).
- 보스 밸런스는 **역할이 나뉜 파티**(전위·딜러·서포터) 기준. Multiplayer Bosses로 인원수 보정.

## 9. 단계별 작업 흐름

1. **모드팩 기반**: 저장소 뼈대, packwiz 모드팩, 최적화·기본 설정, 한글 패치 → 사용자가 실행·테스트.
2. **우리 모드 뼈대 + 첫 유형**: 여신의 질의(전체 3단계 구조, 우선 첫 유형으로 귀결되는 경로), 숙련도·재능·적성·지식, 여신의 서, 스킬 슬롯, **전위 밸런스형** 완성(스킬, 3D 무기, 그림) → 모드팩에 추가해 플레이 테스트.
3. **나머지 8개 유형**을 하나씩 같은 방식으로 추가. 각 유형마다 사용자 테스트.
4. 그사이 보스 재조정, 보스 스킬, 방어구, 강화, 퀘스트북, 스크롤·유물·소환 시스템을 유형에 맞춰 확장.
5. **완성 후** 설치·접속·플레이 가이드를 최종 정리하고 친구들에게 전달.

첫 유형을 무엇으로 할지는 설계자 제안(전위 밸런스형 — 가장 기본적이고 Epic Fight 검 동작을 바로 활용).
